## Phase별 요약

### Phase 9 — SQL 마이그레이션 버그 + 기록 삭제 기능
`@capacitor-community/sqlite`의 Android 마이그레이션 `statements` 배열에 세미콜론으로 연결된 여러 문장을 한 원소로 넣으면 `execSQL()`이 첫 문장만 실행하고 나머지를 조용히 버리는 것이 원인. 배열 원소를 문장 하나당 하나로 재작성하고 자가 치유용 `SCHEMA_V3`를 추가해 해결. 같은 세션에서 `RouteListScreen`에 체크박스 다중 선택 + `Dialog.confirm` 기반 삭제 기능도 함께 구현.
→ [09-track-points-migration-bug.md](./09-track-points-migration-bug.md)

### Phase 10 — 경로가 지도에 다 안 보이던 문제
경로 상세 화면이 항상 시작 위치·고정 줌(16)으로만 카메라를 맞춰서, 실제 이동 거리가 화면 폭(약 300m)을 넘으면 경로 나머지와 종료 위치가 화면 밖으로 벗어남. `MapProvider.fitBounds(points)`를 세 지도 어댑터 모두에 추가해 항상 전체 경로가 화면에 들어오도록 수정. 실제로 걷기 어려운 상황이라 기기 DB에 약 1km 거리의 가짜 경로를 직접 주입해 검증.
→ [10-route-path-not-visible.md](./10-route-path-not-visible.md)

### Phase 11 — 출발/도착 마커 색상 구분
경로 상세 화면의 시작/종료 마커를 "출발"(파란색)/"도착"(빨간색)으로 구분. `MapProvider.addMarker`에 `color` 옵션을 추가하고, `marker-icon.ts`의 공용 SVG 헬퍼로 네이버/카카오/구글 세 SDK 모두 동일한 모양의 마커를 그리도록 함.
→ [11-departure-arrival-markers.md](./11-departure-arrival-markers.md)

### Phase 12 — 이동 거리/시간 저장 + 경로선 색상 + "기록 정보" 패널
추적 중 5초 포인트마다 haversine 거리를 누적해 추적 종료 시 총 이동 거리(Km)/시간을 `routes` 테이블에 저장(`SCHEMA_V4`). 경로 연결선을 RGB(134, 229, 127)로 변경. 경로 상세 화면 우측 상단에 "기록 정보" 패널(이동 거리/이동 시간)을 추가.
→ [12-route-distance-duration.md](./12-route-distance-duration.md)

### Phase 13 — 백그라운드에서 위치 저장이 멈추던 문제
저장 트리거가 JS `setInterval`이었는데, 앱이 백그라운드로 가면 WebView의 JS 타이머가 스로틀링/정지될 수 있어 저장이 멈췄던 것. 네이티브 위치 콜백에서 직접 저장하도록 바꾸고 5초 간격은 경과 시간 체크로 구현. 실기기에서 11분간 백그라운드로 두고 확인한 결과 114개 포인트가 끊김 없이 저장됨을 확인. 이 검증 도중 화면 전환 시 흰 화면 크래시를 1회 목격 → Phase 14에서 별도로 재현·수정.
→ [13-background-tracking-not-saving.md](./13-background-tracking-not-saving.md)

### Phase 14 — 흰 화면 크래시 재현 및 수정
전역 에러 리스너 + 비압축 빌드로 스택트레이스를 확보하고, 네이버 지도 API 키를 의도적으로 무효화해 "인증 실패" 상태를 고정 재현시킴으로써 크래시를 안정적으로 재현. 원인은 인증 실패로 깨진 네이버 지도 객체의 마커에 `.setMap(null)`을 호출하면 SDK 내부에서 예외가 발생하고, 이것이 React 언마운트 커밋 단계로 전파되어(에러 바운더리 부재) 앱 전체가 빈 화면으로 죽는 것. 세 지도 어댑터의 SDK 정리 호출을 try/catch로 감싸고, `ErrorBoundary`를 앱 전체에 추가해 방어선을 마련. 동일 강제 재현 절차로 수정 후 크래시가 재발하지 않음을 확인.
→ [14-white-screen-crash.md](./14-white-screen-crash.md)

## 참고
- 각 Phase의 시각은 실제 작업 완료(리포트 저장) 시각이며, 화면 캡처에 나타난 기기 자체의 시계는 개발 PC와 동기화되어 있지 않아 (기기 시각과 PC 시각이 다르게 표시됨) 이 표에는 반영하지 않았다. Phase 13/14의 "11분 백그라운드", "몇 초 대기" 등 소요 시간 서술은 기기 화면 타임스탬프 간 상대적 차이를 근거로 한다.
