# 23. 기능 추가: 안드로이드 뒤로가기(백키) 동작 재정의

## 요청

기존에는 모든 화면에서 하드웨어 백키를 누르면 앱이 바로 최소화/종료됐다. 요청:
1. 기록/장소 정보 상세 화면 → 백키 → 목록으로("닫기"와 동일).
2. 목록 화면 등 하위 화면 → 백키 → 상위(지도 탭)로.
3. 메인 화면(지도 탭) → 백키 → "종료하시겠습니까?" 팝업(확인/취소).

## 원인

`@capacitor/app` 플러그인이 설치되어 있지 않아, 백키 입력을 가로채는 리스너가 전혀 없었다. Capacitor는 `backButton` 이벤트에 리스너가 하나도 없으면 기본 동작(최소화/종료)으로 그냥 떨어진다.

## 구현

- `@capacitor/app` 플러그인 설치.
- `App.tsx`에 `CapacitorApp.addListener('backButton', ...)`를 앱 전체에서 1회만 등록. 리스너는 다음 우선순위로 동작:
  1. 현재 활성 탭(기록/장소 정보)이 "상세 화면이 열려 있다"는 핸들러를 등록해뒀다면 그것을 먼저 호출 — 상세를 닫고 목록으로(각 탭의 "닫기"/"<" 버튼과 동일한 동작).
  2. 그 외(목록 화면, 설정 탭 등 — 즉 현재 지도 탭이 아닌 모든 화면)에는 지도 탭으로 전환.
  3. 지도 탭(메인 화면) 자체에서는 `@capacitor/dialog`의 `Dialog.confirm()`으로 "앱을 종료하시겠습니까?"를 띄우고, 확인 시 `CapacitorApp.exitApp()`, 취소 시 아무 동작 없이 닫힘(`window.confirm()`은 이 WebView에서 동작하지 않으므로 기존 패턴대로 `Dialog.confirm` 사용).
- `RecordsTab`/`PlaceInfoTab`에 `onRegisterBack` prop 추가 — 각 탭이 마운트되어 있는 동안, 현재 상세 화면이 열려 있는지에 따라 핸들러를 등록/해제한다. 상세가 열려 있으면 그걸 닫는 함수(그리고 "처리했음"을 의미하는 `true`)를, 목록 상태면 `false`(= "내가 처리 안 했으니 상위에서 처리해")를 반환하도록 설계해, App.tsx가 상세→목록, 목록→지도 전환을 명확히 구분할 수 있게 했다.

## 검증

실기기에서 `adb shell input keyevent KEYCODE_BACK`으로 5가지 시나리오 모두 확인:
1. 지도 탭 → 백키 → "종료 / 앱을 종료하시겠습니까?" 팝업 표시.
2. 팝업에서 "취소" → 팝업만 닫히고 앱 유지.
3. 기록 상세 화면 → 백키 → 기록 목록으로 복귀(지도로 안 넘어감).
4. 기록 목록 → 백키 → 지도 탭으로 전환.
5. 설정 탭 → 백키 → 지도 탭으로 전환.
6. 지도 탭 → 백키 → "확인" → 액티비티/태스크 종료 확인(`dumpsys activity activities`에 더 이상 나타나지 않음, 홈 화면으로 복귀).
